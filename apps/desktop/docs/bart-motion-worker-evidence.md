# Bart 执行隔离：实测记录

2026-09-15，Electron 43.3.0 / Chromium 150.0.7871.212，macOS 内建 Retina 显示器报告 120.0006Hz，1180 × 780 CSS px、DPR 2、透明窗口与 vibrancy。对应 [#251](https://github.com/xinyuan0801/OpenAgent/issues/251)。本阶段保留基础安全中止，暂缓优雅回程与通用对外 API。

> **历史记录。** 本文全部数值采集自透明窗口 + vibrancy 的合成路径；该窗口配置此后已从生产移除，应用与 `tests/bart-worker-isolation.electron.mjs` 现在都使用不透明窗口。本文保留的是当时那条路径的测量结果，不代表当前配置；复现方式见下文。

## 测量方法与边界

- Renderer 执行真正的同步忙循环。Electron Main 通过 `beginFrameSubscription(false)` 取得完整内容帧并散列实际角色、文字、页面、滚动和遮挡区域；截图编码在测量后进行。
- Renderer rAF 橙色方块必须冻结。负对照最多排除阻塞前已提交 GPU 工作的 400ms；运动轨道没有这项豁免。每个活动段单独检测 ≥100ms 冻结，不能只看整场分位数。
- 捕获通常约 30fps，回调间隔不是显示器帧间隔。Chromium trace 的 `DirectRenderer::DrawFrame` 是合成提交；M0 另外约束 P99 不超过两个刷新周期，在本设备上约 16.67ms。
- 不把 Worker `performed`、DOM ready 或两次 rAF 当作物理屏幕呈现证明。本文没有独立高速屏幕采集，也没有另一台 60Hz 硬件的实测结果。
- 真实窗口串行运行，测量时不并行构建或单测。M0/生成使用固定浅色主题，完整设置页使用深色主题，避免系统日夜切换改变对照条件；不修改系统主题设置。
- 设置页另有独立的原生 opacity/transform 动画，保持 Main 采集在有限角色动作结束后仍有采样机会。它位于所有被测区域之外；虚线、角色及负对照都单独检查。没有用诊断动画代替产品画面。
- M0 同样使用独立的原生透明度层校准终态后的采样：层覆盖窗口，只有最右侧 12px 有可见像素，全部检测区域均透明。角色、文字与负对照仍各自散列，诊断层不能令它们通过运动断言。连续分析帧按每 CSS 像素一个采集像素缩放，降低 Main 内存开销；窗口本身及准备/终态/交接截图保持 DPR 2。

## 表面选择与预算

每窗口一个专用动画 Worker，直接绘制 DOM 局部关联的 OffscreenCanvas，不将逐帧位图传回主线程。常驻角色保留原生滚动、裁剪和层级祖先。完整生成与跨页使用 WebGL2；穿眼镜头在同一 Worker 的关联 Canvas2D 中绘制真实页面快照与矢量遮罩。

全部小 Logo 使用加速 Canvas2D 的早期样本，中位提交间隔约 24.5ms、P99 50.6ms；关闭捕获仍约 25.0/47.8ms。将不超过 4096 个物理像素的局部表面改用 Worker 软件栅格后，避免了每个小图标刷新 GPU 命令缓冲区的成本。大画布保留加速。

预算为每窗口 96 个关联表面、两个短演出表面、16Mi 像素、64MiB 纹理、单表面最多 256 纹理、纹理最长边 4096。`gpuSurfaces` 诊断字段统计短演出表面，不表示所有加速 Canvas2D 的上下文数量。配置 IPC 最多一条在途、一条最新待发；生成队列最多 8 批，每批最多 16 张。

预热总预算 10 秒，临近播放的封口预算 2 秒。预热字体、Markdown 和静态资源不持交互锁；超预算恢复当前真实页面。回复阴影和镜头遮罩在 ready 前预热，播放时没有像素读回。

## M0 配对结果

同一场景包含 39 个真实角色、回复、两张完整 Harness 卡片、原生滚动/裁剪、设置页遮挡和跨页交接。

| 样本 | Renderer 阻塞 | 合成提交中位数 | P95 | P99 | 最大间隔 |
| --- | --- | --- | --- | --- | --- |
| 正常负载基线 | 0s | 8.326ms | 10.516ms | 13.479ms | 17.575ms |
| 跨段阻塞 | 2s，2600ms 开始 | 8.323ms | 11.465ms | 14.278ms | 26.363ms |
| 跨段阻塞 | 5s，1500ms 开始 | 8.326ms | 10.901ms | 14.168ms | 24.161ms |
| ASAR 内 `loadFile` | 2s，2600ms 开始 | 8.342ms | 11.382ms | 15.039ms | 33.540ms |

同一采集配置下，2s/5s 样本 P99 比正常基线约高 5.9%/5.1%；均通过各活动段冻结检查与真实正文揭示检查。没有将偶发长间隔从统计中删去。

冷加载约 263–301ms，角色资源 ready 约 457–494ms，首次 Main 内容捕获约 536–576ms。这些分别是加载、资源确认和捕获时间，不是物理屏幕的首帧时刻。冷封口约 222–242ms；热预热约 0.1–0.2ms，热封口约 226–270ms。故意阻塞引入的 Host 等待计入总锁定。

连续三轮申请额外表面，每轮触及 96 上限，明确拒绝 9 个，释放后回到原来的 41 个；纹理归零。隐藏后 visible=0、scheduled=false、draws 不再增加；恢复后按当前时钟继续。旧交接令牌不能释放新场景；内容 revision 改变后恢复当前 DOM，焦点与命中同时恢复。

## 生产场景

| 场景 | 2s 阻塞时活动区最大观测间隔 | 5s 阻塞时活动区最大观测间隔 |
| --- | --- | --- |
| 生成接力、镜头与回程 | 36.3ms | 38.7ms |
| 跨页去程 / 回程 | 37.6 / 36.2ms | 43.7 / 35.7ms |
| 穿眼进入 / 返回 | 39.1 / 36.2ms | 37.4 / 36.3ms |
| 完整设置页：打开、切换协调者、派发反馈、关闭 | 37.5ms | 42.0ms |

这些是内容捕获的观测间隔，不是显示器刷新率。负对照在被测区间冻结约 1.5 秒或 4.5 秒。每个动作交接后纹理为零，真实页面可见、非 inert，场景令牌已释放。

- 生产生成一次提交约 5907ms 的完整链。第二张真实 360×200 卡片初始 y=1071，预编排镜头移动 -685px 后位于 y=386。原生参考条与 Worker 纹理共享绝对单调时钟；第二张卡片无需 Host 续播。2s/5s 总锁定约 6141/6640ms，后者含故意阻塞后的交接等待。
- 生成和跨页都在 Worker 内借用常驻角色的实际状态，保留弹簧、表情与时钟；卡片/光标形状暂时接管可见轮廓，回程再交还同一角色。更新过的原生语义优先于旧计划。
- 穿眼镜头一次接收真实 Overview、Bart Thread 快照和 SVG 路径，完整执行 1100ms。冷封口约 0.6 秒，含两页快照与遮罩预热；Host 迟到时保持终态。
- 设置页运行实际 `HarnessSettingsPage`、Dock 和跨页组件，包含协调者切换、引擎标记、目标反馈及持续流动的虚线。有限反馈结束后虚线仍在阻塞期间继续。关闭后短演出画布缩为 1×1，保留上下文但释放纹理与像素预算。
- processing / allow / deny / answer 四种实际干预在 2s 阻塞下完成；延迟回答 token 前 400ms 不出现、650–1400ms 出现、1650ms 后消失，验证下一段也独立执行。
- HTML 文字入场有单独的 Main 采集与负对照，检查阻塞期间的文字像素增加和位移，不借角色运动判定文字通过。
- Playwright 在 75% / 100% / 140% 缩放下验证 Codex、Claude、Pi、Report 四张真实卡片共同准备及完整交接，另检查新内容到达、取消恢复与 Claude 扩展。原生卡片节点保持不变；截图检查了完整字体、换行、图标及内容。

## 失败样本与修正

- 回复首次阴影栅格曾有约 357ms 停顿，镜头冷遮罩曾有约 340ms 空窗；改在 ready 前预热代表帧并做一次准备读回，后续活动窗口不豁免这些位置。
- 强制 `WEBGL_lose_context` 曾产生 Chromium 缺失 mailbox 日志；改为复用上下文、交接后释放纹理并缩小空闲画布。
- 设置页曾有 Main 捕获 191ms 空窗，而同区间合成提交最大间隔仅 14.9ms；减少采集内存开销并校准持续采样后重测，未把该失败样本当作通过。
- 系统夜间主题曾让固定浅色 M0 背景使用浅色原生文字，正文像素断言失败；原生 DOM 截图确认也是同样颜色。固定测试窗口主题后重跑了完整套件，没有放宽正文断言。
- 最终 checkout 验证暴露镜头准备把计时数字变化当作新内容，从而安全退出。版本比较现在忽略滚动计时数字，仍因真实内容、几何或主题变化收口；补充两类变化的回归后，进入/返回的 2s、5s 原生阻塞再次通过（`azaJlN` / `bXuAOA`）。
- 同轮正常负载样本出现 206–222ms 的长提交间隔，P99 没有暴露这些少量长间隔。M0 采集改为一次取得帧像素、按行散列各区域，减少逐区域 nativeImage 裁剪的额外分配，并增加常驻角色区间的 100ms 冻结断言。修正后基线 `CIFfui` 的提交中位数/P99/最大间隔为 8.323/12.061/16.942ms；原始异常样本保留在 verification 产物，未作为流畅度通过证据。
- 更严格的检查随后在大画布进入终态时发现约 250ms 的采集空窗，期间合成提交仍连续；减少像素分配及小尺寸校准标记不能消除它。使用上述透明层维持采样后，5s 样本 `zeWDlr` 的真实常驻区域最大观测间隔为 50.273ms，提交 P99/最大间隔为 13.684/18.657ms。捕获空窗不直接等同于产品冻结，也不作为通过样本。
- 复审补齐根节点被外部移除后的资源释放、按 SVG 实际 CSS 尺寸及 ResizeObserver 更新栅格分辨率、封口两秒到期立即中止慢快照并释放全局场景租约。相关生命周期与尺寸回归已加入测试。

## 复现与产物

下列命令现在创建的是不透明窗口，因此**不会**重现本文表格里的数值：需要先把 `apps/desktop/tests/bart-worker-isolation.electron.mjs` 与生产窗口恢复到 `f3b948f5`（Overview 改为不透明背景）之前，再由当时的脚本采集。

```sh
pnpm --dir apps/desktop test:bart-isolation
# 单个场景，先构建 Lab：
pnpm --dir apps/desktop exec vite build --config labs/bart/vite.config.ts
node apps/desktop/tests/bart-worker-isolation.electron.mjs --generation 5000 1400
node apps/desktop/tests/bart-worker-isolation.electron.mjs --camera 2000
node apps/desktop/tests/bart-worker-isolation.electron.mjs --settings 5000
node apps/desktop/tests/bart-worker-isolation.electron.mjs --message 2000
```

脚本输出原始目录，包含区域统计、实际内容帧、资源计数及 trace。可用 `BART_ISOLATION_OUTPUT` 指定目录，`BART_TRACE_ONLY=1` 跑 M0 无捕获对照，`BART_ISOLATION_ENTRY` 指向 ASAR 内入口。完整套件自动校验 ASAR 加载，使用生产 sandbox/contextIsolation/webSecurity。
这套检查不在 CI 中运行：托管 runner 的原生窗口只有 1024×653，坐标、合成手势和准入预算都不成立，
CI 也没有 `bart-isolation` 步骤。它只在真机上手动执行，入口是
`pnpm --dir apps/desktop test:bart-isolation`，所以本文记录的数值是测量时的快照，
不表示此后每次改动都被重新门禁。见 [Bart 隔离测量](../../../docs/agents/bart-isolation.md)。

本轮目录：基线 `KOoAA9`，M0 2s `2cKcKg`、5s `E9Ahy4`，ASAR `UfsO13`；干预 `Ld3N6i`；生成 `N7cZQc` / `baYbL3`；跨页 `GcOfcK` / `vl5tMd`；镜头 `v4Bih5` / `9HFtg9`；设置页 `1Vf0B0` / `4fVQxn`。目录名均带 `bart-isolation-` 前缀，位于运行机器临时目录。可提交的数值摘要在本文，完整产物由上述命令重新生成。

基础正确性另由真实 Worker 模块及 DOM 测试验证：旧 play/release/landing、资源所有权、隐藏恢复、Canvas2D context 丢失、DPR 变化、准备超时、StrictMode、配置合并、内容 revision 及焦点。它们不替代真实窗口的连续性证据。

## 打断后的终态交接（#272）

- 设置页回程可能早于页面收拢结束。过去先撤掉飞行画布，但 App 的 Dock 仍因 `settingsOpen` 隐藏；原生复现中，25/70/120ms 打断分别出现 7/10/6 个空白显示帧。现在短演出保留终态及所有权，等页面 `closed` 后一次提交真实 Dock，再释放画布。等待期间仍能再次反向。
- 穿眼镜头原来只画路径和眼睛，缺少常驻角色的内部阴影、主题亮边和 Dock 外部阴影。镜头现在准备一张含透明留白的角色端点纹理，在 Worker 中按同一绝对进度衔接角色表演；回程到零时保留完整原生外观，直到 Host 交接。序列化滤镜显式使用 sRGB，防止近黑色经过 linearRGB 量化后改变颜色。
- 只有页面允许交接后才提交角色落地；Worker 复制姿态和时钟，避免落地确认与再次反向竞争时，两个常驻位置共享可变状态。三张镜头纹理共同计入 64MiB 预算，常规窗口保留原生密度，大窗口统一降低采样密度并为其他资源留出余量。
- `bart-handoff.electron.mjs` 使用与 App 一致的 Dock 隐藏条件和页面关闭顺序。深浅主题各覆盖四个早期打断时机、等待交接时再次反向，以及 Renderer 阻塞期间的镜头返航。测试同时检查 DOM 所有权和原生合成像素：本体区域无空白/变色，光晕环带在 Worker 终态与真实 Dock 之间保持连续。测试已纳入 `test:bart-isolation`；这些像素检查补充 2s/5s 阻塞与 120Hz 合成 trace，不把“动画已完成”当成“交接无闪烁”。

```sh
node apps/desktop/tests/bart-handoff.electron.mjs
```
