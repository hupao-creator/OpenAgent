# Overview liquid glass 捕获与提交

`@liquid-dom/core@0.1.1` 的 pnpm patch 修复两条时序：

- 布局同步发生在浏览器 paint 前，此时 DOM 的 cached paint record 可能缺失或对应旧尺寸。Renderer 只在原生 `paint` 回调内捕获 DOM；任一待捕获层未完成时，不用不完整纹理覆盖上一张完整画面。
- 原库的 `paint` 只更新纹理，不提交画面。WAAPI 自动取景没有 React 逐帧更新，因此 demand 模式会停在过渡中间。捕获完成后直接合成、提交，不依赖悬停跟帧的 220ms 窗口。

窗口增大时，等待新捕获期间将上一张完整画面缩放至新画布，避免原来的局部复制在右侧、底部留下黑边。这里不设置“失败若干帧后放行”的计数器；失败仍然不能提交不完整画面。失败的 paint 会主动请求下一次 paint，成功后停止，销毁时取消，恢复不依赖新的鼠标或 DOM 变化。

原生 paint 中的异常保存在 Renderer，并通过画布事件唤醒受保护的 React 帧循环；既有 onError 会把 Overview 降级为普通 DOM。

相机手势只触发画面失效。舞台尺寸和浮条盒子变化仍通过各自的尺寸观察器更新布局。

## 成功捕获也可能产生黑帧

修复捕获异常后，真实三卡片实例仍可在点击空白回到自动取景时闪黑。逐帧采集发现，
这些黑帧对应的 `copyElementImageToTexture` 调用全部成功；不能用“没有异常”判断
画面正确，也不能靠异常重试保护这条路径。

真实卡片还保留着已结束的 Bart 操作装饰层：完成动画用 `fill: both` 停在透明末帧，
子节点的 sweep/pulse 动画仍参与捕获。GPU 读回确认，这时源纹理尺寸完整，但背景
已经被捕获为透明黑。移除已结束的装饰层可消除这个长期触发条件；不过重放完成动画
后，在尚未结束的淡出阶段仍可触发。仅移除透视或 `will-change` 也不能解决问题。

Electron 固定为 44.4.3（Chromium 152），包含 Chromium 的
[Canvas 子树合成层修复](https://chromium.googlesource.com/chromium/src/+/1337fde1b6bb61c6dba4b184df3f30536a826573)。
旧实现可能把 Canvas 子节点关联到某个后代的独立 PendingLayer，导致捕获整棵内容时
只得到局部图层；修复强制合并后代层。这个路径不会抛出捕获异常，因此仍需保留之前
针对失败拷贝的库补丁，并用最终画面验证运行时升级。

`bart-edge-complete` 保留原有淡出过程，末帧用 `display: none` 结束整棵装饰子树的
绘制，避免只隐藏像素却留下捕获层。相机运动、透视和 Liquid glass 保持启用。

复核这类问题时，先在受影响的真实实例中拖动三张卡片，再点击空白回自动取景；记录
最终合成画面的连续帧，并核对自动取景完成、画布仍启用。还要覆盖缩放后的返回。
保留原样／修改／恢复原样的对照证据。下面的 GPU fixture 使用产品 CSS，覆盖三个
带 Bart 完成装饰的卡片，先将淡出暂停在 610ms，重复相机动画，再让装饰退出布局，
重复相机动画。它仍不能代替
受影响真实实例的复现与回归。

## Bart 截图就绪

刚挂载的 LiquidCanvas 可能仍是 300×150 的默认尺寸，GPU 初始化完成也不代表已经
捕获 HTML 并提交完整画面。Renderer 仅在成功提交后设置 `data-liquid-frame-ready`，
场景变更、待捕获内容、错误和销毁会清除此信号。Bart 在页面仍可交互的准备阶段等待
该信号（普通 DOM 降级无需等待 GPU），再锁定页面版本并开始截图；保持原有 10 秒
准备上限和 2 秒锁定上限，不再在锁定后用“纯色重拍”猜测初始化是否完成。

快照把 Canvas 转为位图后跳过其 DOM 子树，避免 html-to-image 继续克隆已经包含在
像素中的 Overview 卡片。原生测试同时覆盖首次捕获失败时不能提前报告就绪。

## 原生回归

在具备图形会话与 WebGPU 的机器上执行：

```sh
pnpm --dir apps/desktop test:liquid-runtime
```

可通过 `LIQUID_TEST_ELECTRON=/absolute/path/to/Electron` 用同一测试对比旧运行时。
结果 JSON 记录 Electron 和 Chromium 版本，避免实际测到另一份二进制。

该命令开启独立 Electron 窗口与临时数据目录，使用仓库的 Electron 和真实 GPU。覆盖 360ms 原生动画的连续提交、15 次自主捕获重试失败、画布扩容、解除故障后无需 DOM 变更即可恢复、异步提交异常接回受保护的 render，以及闲置和销毁后不再提交。控制台错误通道先用 sentinel 验证，避免空日志假通过。采样最终合成画面的空白区域，黑帧和 GPU/控制台错误会令测试失败。日志及失败截图保存在命令输出的临时目录。

这项真机 GPU 回归独立于 GitHub Actions `verify`；CI 的 DOM 测试验证相机失效路径，不把缺少原生 GPU 的环境当成通过。本地原生结果应随 PR 记录。

升级 liquid-dom 时同时检查 ESM/CJS 补丁是否仍需要，并重新运行原生回归。
