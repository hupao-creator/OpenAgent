# Bart 生成场景的阶段契约

承接 #5、#7，解决 #8。此契约仅适用于卡片生成；导航快照可以采用不同的内容失效策略。

## 输入与场景不是同一个版本

生成演出表达一份已提交内容，不要求它在首帧或播放期间仍是最新业务内容。
内容新鲜度、输入内部一致性、目标几何有效性分别处理：

- **取样**：预热结束并获得原有舞台租约后，在一个同步 Host task 内为整个批次固定 DOM 与计算样式。复制现有卡片，不重新实现卡片组件，也不保留 Thread 聚合。
- **制备**：排字测量与异步纹理序列化使用同一份固定副本；后续文本、状态、类名或 busy 状态变化不重采样。实时卡片仍由 React 更新。
- **准入**：继续校验实时目标、根节点、滚动容器和工具栏的几何；工具栏的出现或替换也会失效。真实几何变化重新准备，不延长原有封口截止时间。资源失败仍终止，不盲目重试。
- **播放**：保持 #7 的规则，普通业务更新不截断或重启既定 Worker 程序；完整显现及返航后才交接。
- **交接**：移除覆盖、释放租约，露出最新原生 DOM，不把旧快照回写业务状态。取消、导航、目标删除、根视口变化和媒体偏好失效保留安全退出；媒体偏好监听也覆盖准备阶段。

因此，“与实时内容不同”不再是生成场景的准备失败。也不能只删 revision 校验后继续跨 await 读取真实卡片，否则排字与纹理仍可能来自不同版本。

## 副本的生命周期

`freezeCardDOM` 将已有 DOM、计算样式、伪元素样式及选中的图片来源复制到短期、inert、不可见的闭合 ShadowRoot。应用选择器、重复 ID、事件监听与 React 所有权不进入这份输入。画布像素、表单值和滚动位置属于取样结果。

`captureMotionCard` 在副本上测量逻辑卡片坐标；原生卡片矩形仅用于定位 Worker 世界坐标。缩放不改变纹理密度预算。`CapturedMotionCard` 只暴露一次性制备与幂等释放，不向后续场景阶段暴露可变 DOM。

批次在第一次异步编码之前完成全部取样，仍按原来的顺序制备纹理。副本在制备完成或失败时释放；超时或取消立即移除所有副本，包括尚未编码的卡片。迟到的 bitmap 仍观察 AbortSignal 并关闭，不能上传或重放。单张纹理、批次卡数、预热与封口预算不增加。

本改动不保证持续几何变化或坏资源下必定播放，也不暂停业务更新来制造安静窗口。不扩展公共 Motion API、不实时追加 token、不改变动画节奏与 Worker 执行后端。

## 回归入口

- 生产生成组件 DOM 测试：在捕获、上传、借用角色、首帧边界更新内容；固定输入只运行一次。真实几何仍重试，超时与生命周期退出仍清理。保留播放及返航期间更新、最终最新内容交接的测试。
- 卡片资源 DOM 测试：使用真实取样器，只替换 jsdom 缺失的布局与像素编码，证明测量与延迟编码读取同一副本，覆盖同步失败、解码失败、取消后的迟到 bitmap、单次消费和预算边界。
- 现有真实 Chromium/Worker 生成回归：在 SVG 解码期间通过原有按钮持续更新真实 React 卡片，验证整个批次先取样、仍在原有预算内起飞、最终交接最新内容；原缩放、播放与取消用例保留。

原生 macOS Bart 隔离与视觉验收依然使用现有真机入口；DOM 用例或普通 headless Chromium 不构成高刷新率或物理显示帧率证明。
