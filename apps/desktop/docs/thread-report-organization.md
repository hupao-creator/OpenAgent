# Thread archive and Execution-bound reports

Implements [Issue #83](https://github.com/xinyuan0801/OpenAgent/issues/83), with Report-to-Agent archive propagation defined by [Issue #131](https://github.com/xinyuan0801/OpenAgent/issues/131) and failed-Execution auto-archive by [Issue #139](https://github.com/xinyuan0801/OpenAgent/issues/139).

## References and ownership

A report has an ordered `relatedExecutions` collection of `{ threadId, executionId }` pairs, with one Execution per Thread. Each explicitly selected Execution must exist in that Agent Thread and have public status `completed`. An older completed Execution remains eligible when a newer one starts or fails. Active background work does not affect eligibility. Title and HTML updates preserve relations unless the caller explicitly replaces them; failed writes preserve the prior committed report and its overview result.

Core owns report relations and archive state. The owning Harness resolves an Execution ID from its opaque Session state through a pure public lookup. Core validates the public result while the report and explicitly referenced Thread scopes remain locked through persistence; a concurrent deletion cannot invalidate a newly committed link. Updating content alone does not revalidate or remove existing missing targets. Core never inspects native turns or private Session data. Harness renderers separately resolve the same reference into their existing historical document view. Report HTML remains isolated: links and navigation belong to the Host UI, with no bridge exposed to the HTML.

## Overview

The two exclusive views are:

| View | Candidates before consolidation |
| --- | --- |
| Default | Unarchived reports and unarchived Agent Threads, whatever their latest Execution status |
| Archived | Archived reports and Agent Threads |

An interrupted Execution is not a failure: an unarchived Thread whose latest Execution is `interrupted` remains a Default candidate. A failed latest Execution reaches Archived through auto-archive, never through its status alone. Apply the current tags to these candidates, then consolidate: hide a candidate Agent card only if any candidate report links to that Thread's latest Execution. Invisible reports do not hide cards. Counts and empty states use the same resulting collection. A report's association entry is not another independent card. Archive and tag choices remain selected when opening and returning from a reading view, including an empty Archived view. A view with no tag choices hides the filter bar and temporarily ignores a tag chosen in the other view; returning restores that selection.

Relations stay pinned as Executions, reports, tags and archive state change. A new Execution uncovers the Agent card until a visible report covers that new Execution. Replacing or removing the last covering relation similarly uncovers the card if it remains a candidate.

## Reading and archive

At link activation, compare its explicit Execution with the Thread's current latest Execution. Open the normal Thread view when equal; otherwise ask the owning Harness to open exactly that historical document. A missing Thread or Execution is unavailable, never replaced silently with the latest result. Every report relation is accessible through the expandable list. Later Executions do not force a reader out of the page they opened.

Archiving a Report also archives an existing Agent Thread identified by `relatedExecutions.threadId` only when the referenced `executionId` equals that Thread’s current public latest Execution ID. Historical or unavailable Execution references, Threads without a latest Execution, and missing, deleted or non-Agent targets are skipped. They do not block archiving the Report or other eligible Agents. References stay pinned to their original Execution IDs; already archived targets remain archived. A report without associations archives normally. Repeating archive reapplies the latest-Execution condition to current associations, without advancing already archived Agent revisions. Archiving an Agent does not archive any Report. Unarchiving either object changes only that object.

A failed latest Execution archives its unarchived Agent Thread in the same Core state commit that publishes the failure, with no user action and independently of the Overview being open. Every Harness follows this, for normal runs and runtime recovery alike. The failure fact and the archive flag share one authoritative commit, so persistence never observes one without the other and a failed write publishes neither. The same failed Execution archives once: a repeated observation, a restart replay or a late notification for a superseded Execution leaves the Thread where the user put it, and a later Execution that fails archives again. Core judges only the public latest Execution status; a recoverable tool error, a waiting-for-user state or a voluntary interruption is not an Execution failure, and message text is never scanned. Auto-archive reuses the explicit semantics below, including the submission boundary, and never archives a Report or a Bart Thread.

ReportService serializes report edits, deletion, archive and history reset. Archive takes one durable Core state command holding the report and every referenced Thread scope; it checks that the referenced Thread set still matches and evaluates each latest Execution ID from public observation while those scopes are held. A newer latest Execution committed before this check makes that Agent ineligible. Report and eligible Agent flags commit in one SQLite transaction, then publish together to Renderer and Bart reads. Failed preparation or transactions preserve all previously committed flags and content; a lost post-COMMIT acknowledgement follows the existing storage recovery contract. Concurrent Thread archive, deletion, metadata and Session commits serialize on their Thread scope; unrelated Threads may continue. Default/Archived candidates and counts derive from the committed aggregate using the same consolidation rules above.

Archiving retains content, timestamps and relationships and does not open a Handle, start, interrupt or alter existing Harness work. An archived Agent Thread is absent from Bart's Thread list and rejects appended tasks through the same submission boundary used by GUI and Bart. This guard also applies to stale IDs, old list results and already-open composers; a send waiting for Handle opening rechecks archive before entering the runtime. Work admitted before the archive commit may continue, and its observations remain valid. Rejection creates no Execution and never restores the Thread. Explicit Agent unarchive restores listing and submission. Existing execution interactions remain governed by Harness lifecycle rules; historical controls cannot submit stale responses. Core compares only the reference and public latest Execution ID; it never resolves historical Executions or interprets Session state to archive a Thread.

## Evidence

Report value tests cover reference parsing; archive persistence tests cover rollback, crash recovery and command races; auto-archive tests cover same-commit durability, restart replay, explicit unarchive and racing deletion; Service regressions cover GUI/Bart admission, aggregate publication and active background work. Overview tests cover committed cards and counts. [Property tests](report-archive-property-testing.md) additionally generate the reference rules, the Overview hiding biconditional, the strictly-later re-archive rule, the archive's affected set under a controlled interleaving and whole-aggregate archive durability, with three temporary mutations detected and replayed. The delivery PR binds its acceptance criteria to these regressions, independent reviews and isolated desktop verification on the final head. The architecture map links the current owners and tests.
